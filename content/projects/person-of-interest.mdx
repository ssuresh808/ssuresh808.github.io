## Problem

Face recognition demos usually do identity matching: is this the same person as that one? That is a closed-world problem with a known gallery. I wanted the harder, more realistic version: describe someone in natural language ("a woman with curly dark hair, glasses, and a thoughtful expression") and retrieve the closest faces from an open corpus, then explain why each result was returned. The query has no fixed schema, the matches are not guaranteed to exist, and the system has to operate on narrative rather than labels, the way a witness describes someone.

## My contribution

I designed and built the whole system. SigLIP-2 encodes text and faces into one shared embedding space. A FAISS IVF-Flat index holds normalized face embeddings for cosine retrieval, built once and cached on disk. Qwen2.5-VL-7B captions each retrieved face in the context of the query so the user can see why the system thinks it fits. A NiceGUI front end ties it together. The eval harness synthesizes queries from CelebA attribute labels, scores Recall@K and mean reciprocal rank, and measures latency at p50, p95, and p99. SLURM scripts package the index build and evaluation for a shared GPU cluster.

## Architecture

Three components with three roles. SigLIP-2 does the alignment: text and image embeddings live on the same unit hypersphere because contrastive training put them there, so retrieval is angular proximity. FAISS does the search. Qwen2.5-VL does the reasoning: it reads the query and the retrieved face and writes a sentence about whether they match and where the system might be wrong.

## Key decisions

**SigLIP-2 over CLIP, as a hypothesis to test.** SigLIP's sigmoid loss should produce a more uniform embedding distribution on the hypersphere than CLIP's batch softmax, and that uniformity should translate into better recall for description-to-image retrieval. I wrote this down as a pre-registered ablation (CLIP-ViT-L/14 vs SigLIP-2 base vs SigLIP-2 large on CelebA) with the hypothesis and metrics fixed before the run.

**A separate vision-language stage for explanation.** Retrieval and explanation have different jobs. Keeping them separate means the index can be rebuilt without touching the explainer and the explainer can be swapped without re-indexing.

**Demographic attributes excluded from query synthesis.** The eval deliberately does not build queries from CelebA labels like Male, Young, Attractive, or Chubby.

**An honest eval.** CelebA attributes are noisy and not exhaustive, so treating the original sample as the only gold target lower-bounds true retrieval quality. Absolute Recall@1 will look low; relative comparisons between encoders remain valid because the same noise affects all of them.

## Evidence

Pipeline validation on a 500-image synthetic corpus that mirrors CelebA's attribute structure. The encoder in this run is a deterministic hash over attribute combinations, not a real visual encoder, so these numbers confirm the wiring from query to encode to search to metrics. They say nothing about SigLIP-2 versus CLIP.

| Metric | Hash encoder, 500 synthetic images |
| --- | --- |
| Recall@1 | 0.474 |
| Recall@5 | 0.877 |
| Recall@10 | 0.965 |
| Recall@50 | 1.000 |
| Mean reciprocal rank | 0.650 |
| p95 query latency | 0.12 ms |

The real-model ablation is scripted in `slurm/ablation.sbatch` and has not been run yet. The repo README will carry the measured numbers when it completes.

## Tradeoffs and next steps

The real-model run is the obvious next step and depends on GPU time. Beyond that: IVF-Flat versus brute force at the full 200k-image scale, and how much the explanation stage costs per query.
